## 本轮行为
- USART2 的 HDZ601 yaw 作为朝向来源；角度解包后跨 359°/0° 连续累计。
- 起点仍是场地 (285,80) cm，车头朝图片上方。上电/位置初始化后第一个新鲜 IMU 读数定为零，顺时针为正；不是磁北。
- 编码器仅提供车体左右/前后位移，原轮径和位移校准系数保持不变；四轮差速不再计算定位朝向。
- IMU 保留 64 个带接收时刻的角度。用 encoder1.last_tick 插值得到轮子采样时的角度，以上下两次角度的中值旋转本周期位移。再沿用原场地位姿历史，按视觉观测时刻转换物块位置。
- IMU 时间戳取有效姿态帧最后字节到达 USART2 的时刻，排队时间不会被误当成新数据；应答帧不刷新姿态年龄。模块内部解算延迟没有硬件时间戳，尚未补偿。
- 没有首帧或 IMU 年龄大于 400 ms 时，停止生成新位姿并清空可插值历史，点选行驶走底层减速等待。不会回退到编码器航向。KEY4 仍立即停。
- IMU 失效期间的编码器增量不追补；如果这时移动过车，应重新摆到起点复位后再检查绝对位置。失联期间转过超过 180° 也无法可靠还原累计圈数。
- 追球 case、追球 PID 参数、夹持、视觉端及主控视觉解析未改。原加减速 100 cm/s²、轮速/PWM 90%、点选转速 180°/s 保持原样。

## 页面
V7 延续 V6 的紧凑数组，只新增末尾 [IMU已建立,年龄ms或null,原始yaw×100或null,位姿朝向可用]，仍用 CRC、64 字节分段和 150 ms 上报。
箭头与“小车（IMU 朝向）”使用同一份 IMU 定位角度；另显示 IMU 状态、年龄、原始 yaw。原始 yaw 没有减启动零点，与场地朝向数值不同是正常的。旧 V6 等遥测仍能读取，并标为旧版编码器朝向。

## 先做的实车测试
1. 摆到原定起点、车头朝图片上方，上电保持静止，等待页面 IMU 正常。
2. 不按 KEY1、不点击场地，先手动顺时针转 90°；页面车头应指向右，朝向约 +90°。再反转回原方向，应接近 0°。
3. 保持朝向，轮子贴地向前推一段已知距离，确认场地坐标变化。再做点选测试。
4. 如果顺时针转动却显示负角度，把 project/Core/Inc/imu.h 的 IMU_YAW_SIGN 从 1.0f 改为 -1.0f 后重新编译。本地说明书未声明方向，当前保留旧 IMU 的正号；实车安装方向尚未验证。比例校准仍为原来的 359.6，没有改模块参数。
