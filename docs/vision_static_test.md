# USART6 / RV2 静止视觉联调

最新遥测为 V3 紧凑数组、150 ms 一帧；主控自动夹持仍每 5 ms 判断。下方旧版本说明保留作历史，最新格式见文末。

当前固件匹配 GitHub `codex/uart6-vision-oled` 分支的 `vision_simple_v2`，复用提交 `ab6c6fe` 的 `vision_simple.c/.h` 解析器，并在主控本地修正年龄累计和 400 ms 超时。香橙派视觉代码未修改；主控不再发送 JSON 任务。


## 稳定显示更新

- 主控遥测间隔从 200 ms 缩短到 100 ms，保留 64 字节分段、至少 5 ms 间隔，以及上一帧未完成时跳过新帧的限制。
- 页面标题下显示“无线遥测 v2 · 400 ms · 实测计时”。主控与页面均在累计年龄大于 400 ms 时判过期，恰好 400 ms 不过期。测距有效窗口仍为 150 ms。
- 超过实时窗口后，用灰色虚线点保留“上次位置”，明确显示累计年龄，不冒充实时坐标，所有历史点的测距有效显示为 false。累计年龄达到 1.5 秒清除。
- 新的正常观测替换历史位置；重复帧不能延长历史保留时间。明确无目标、相机故障/溢出、视觉连接断开或网页断开时立即清除。
- 此改进减少视觉上的闪烁，但不会降低相机推理耗时。若长期只有灰点，仍需根据原始报文年龄和实际图像帧率检查视觉端延迟。
- 只刷新桌面 HTML 即可获得灰色历史显示；烧录本目录稳定显示固件后再获得 100 ms 遥测间隔。视觉程序和电机锁止未改。

## 本次无线遥测修复

用户实测：主控已接收视觉数据（link=1、RX 增加、bad=0，count=7），但电脑收到的 JSON 丢失中间内容。此次针对长报文连续发送作改进，尚需实测无线链路确认。

- 视觉口仍为 USART6 / vision_simple_v2，不修改香橙派程序。
- UART5 遥测改为紧凑 v2，一帧保存全部当前上视目标。12 目标测试约 350 字节，原约 1.6 KB；帧长会随数字长度变化。
- 每次最多发送 64 字节，完成后至少留 5 ms 间隔，由 5 ms 主循环调度继续发送，无阻塞等待。每 100 ms 尝试生成一帧；前一帧未完成时跳过本帧，避免积压旧位置。
- JSON 正文之后增加 `*XXXX` CRC16/CCITT-FALSE。目标数组项为 `[类别,径向距离mm,角度百分之一度或null,测距有效位]`，XY 在页面还原，不重复发送。
- 页面兼容旧 v1 和新 v2，但旧页面不认识新 v2。重新打开桌面 HTML 后，标题下必须出现“无线遥测 v2”。
- 页面明确区分 CRC 损坏、JSON 不完整和字段错误；导出记录包含成功与失败原始报文，便于继续排查。
- 新页面只累计实际分段接收耗时和页面等待，已去掉理论串口耗时、每段 10 ms 预算及额外 6 ms 裕量；大于 400 ms 的点仅作为灰色历史位置短时显示。无线模块未报告的内部延迟不再人为估算。

重新烧录此目录的修复版 HEX，断开串口后刷新/重新打开桌面页面，再连接 UART5。若仍有校验错误，导出记录并提供无线模块型号；不要修改视觉端协议，也不要把 valid=0 当成未检测到目标。

## 上板操作

1. 烧录交付目录中的 `静止视觉联调_UART6_RV2_稳定显示.hex`，或使用原 Keil 工程当前生成的 AXF。
2. 香橙派保持该分支原有 RV2 服务。该分支启动脚本默认 `/dev/ttyS6` 和 `vision_simple_v2`。如果之前手动改成了 `rescue_json_v2`，停止该进程后恢复原服务/启动参数；不要同时运行两个占用同一串口的视觉进程。
3. 断开网页串口，刷新桌面的 `静止视觉XY联调.html`，重新连接现有 UART5 遥测 COM 口（115200 / 8N1）。同一 COM 口不能被旧 SerialWeb 或另一个标签页同时占用。
4. 观察视觉 RX 是否增加、CRC/格式错误是否停止增加；“任务确认”应显示“RV2 / 不适用”，全局就绪显示“RV2 / 未提供”，视觉 TX 保持 0 是正常的。
5. 放置物块，检查上视帧编号、目标列表和 XY 点。绿色实心为该目标测距有效，橙色空心为估计；角度 NA 或距离未知时不绘制假坐标。

## 接线

| STM32 | 对端 |
| --- | --- |
| PC6 / USART6 TX | 香橙派实际视觉串口 RX（RV2 仅接收观测时不需要主控发送） |
| PC7 / USART6 RX | 香橙派实际视觉串口 TX |
| GND | 共地 |
| PC12 / UART5 TX | 保留原遥测链路；直连 USB 串口时接其 RX |
| PD2 / UART5 RX | 保留原遥测链路；直连 USB 串口时接其 TX |

两路均为 115200 / 8N1；视觉口为 3.3 V TTL。

如需手动启动，在香橙派真实视觉工程目录运行（串口按实际接线确认）：

```sh
./tools/run_dual_orangepi.sh --controller-port /dev/ttyS6 --controller-protocol vision_simple_v2
```

## 协议与有效性

报文示例：

```text
RV2,upper,42,86,ok,1,green,450,1,0,30.00*CBDC
```

每行以 LF 结束，星号后为 CRC16/CCITT-FALSE。上下视独立接收；每帧最多 12 个目标。解析器也兼容 RV1，但 RV1 无角度，不能生成 XY 点。

- X 向右、Y 向前，单位 cm：`X=d_mm*sin(angle)/10`，`Y=d_mm*cos(angle)/10`。
- 原点沿用视觉标定约定，不自动等同于车头或夹爪。位置通常对应可见贴地边缘。
- 接收器保留 `distance_valid`、`angle_present`、`angle_valid`、`in_roi`。达到 150 ms 后测距有效位清零，累计年龄大于 400 ms 后观测不可用；重复图像不刷新期限，下视数据不会保活上视。
- 主控累计视觉报文年龄、UART6 首字节至换行实测耗时以及接收后至遥测生成的等待时间；页面继续累计首段接收至完整行的实测耗时和收齐后的等待。未报告的相机内部延迟、发送排队和无线模块首段交付前的延迟无法精确测得；“测距有效”不等于完成实车精度验收或允许行驶。
- RV2 不提供任务 ACK、全局就绪、全局危险判断或跟踪 ID。遥测 `ack=0, ready=0`，`danger=1` 保守保留；页面根据显式协议字段按各目标测距有效位显示。图中 `#1/#2` 只是本帧数组序号，不能用于跨帧锁定。
- `vision.upper` 和 `vision.lower` 可直接读取；`vision_set_task()` 当前返回 false，不发送命令。原 case 骨架仍在，任务规划留在主控中。

## 静止限制与恢复

`VISION_STATIC_TEST=1` 时，四路电机 EN 强制关闭、PWM 强制为零；串口 RUN/ENABLE/TARGET/PID 命令被拒绝。底层驱动、编码器、里程计保留。

将 `vision.h` 中 `VISION_STATIC_TEST` 改为 0 并重新编译烧录可恢复普通 case 骨架和电机遥测；这不会把 RV2 改回 JSON 任务协议。

## 年龄修正版（2026-11-14）

- 每次计算都以保存的原始年龄及时间戳为基准，不把上次计算结果再次累加。
- 过期后仍输出增长的年龄，不再退回视觉报文原值；未知年龄仍为 null。
- 主控观测、遥测生成和页面显示均使用 `age > 400` 判断本地过期。
- 视觉主动上报的 stale/fault、未知坐标和无效测距仍保留，不会因放宽本地超时而变成有效。
- 上述年龄是已知阶段的累计值，不包含无法测量的无线内部延迟；不会加假定裕量补齐。


## 下视 ROI 自动轻夹联调（2026-11-14）

本版底盘 EN/PWM 继续锁定为零，只有夹爪舵机根据下视自动动作。香橙派 perception 代码未修改。

- 上电保持默认 50° 松开。下视新鲜正常帧中，恰好一个 green/black/orange 物块 in_roi=1，且 ROI 内无 blue 危险物时，立即给舵机 100° 指令。
- 新帧中物块离开 ROI、画面无目标、多个物块入区、危险物入区、下视过期或故障时，给 50° 松开指令。失去下视更新时，即使上视继续更新，也会在下视累计年龄大于 400 ms 时松开。距离/角度可未知，不作为 ROI 判断的必要条件。
- 不增加连续帧门槛；本版就是测试 ROI 入区/出区是否稳定，若识别来回跳变，舵机会随之开合。重复图像不刷新保活时间。
- 静止测试模式屏蔽原按键舵机控制，避免 140° 覆盖自动轻夹；普通模式保留原按键逻辑。
- 页面顶部增加下视类别、逐目标 in_roi、帧编号、独立累计年龄、目标数/入区数、主控舵机指令。指令角度没有物理反馈，不等于已夹紧。
- 紧凑 v2 遥测增加 g=主控舵机指令，以及 n=[下视帧编号,年龄或null,状态,新鲜位,[[类别,in_roi],...]]。原上视字段保留，整行 CRC、64 字节分段、5 ms 间隔继续使用。测试 12+12 个目标报文为 441 字节；实际长度随计数和数值变化。
- 下视失效时页面清除当前 ROI 列表，不用历史位置保持入区状态。页面断开不会向主控发指令，主控仍根据视觉自主开合。


## 无线减负 V3（2026-11-14）

仅调整 UART5 遥测及页面解析，香橙派视觉、主控 vision.c、底盘与舵机驱动及按键逻辑未变化。上下视所有目标保留，仍每路最多 12 个，不截断。

线上报文为 JSON 数组加 `*CRC16\r\n`：

`["V3",tick,link,rx,bad,uart_errors,drops,upper_frame,upper_age,upper_status,upper_fresh,fault_code,[[kind,distance_mm,angle_cdeg_or_null,valid],...],servo_angle,[lower_frame,lower_age,lower_status,lower_fresh,[[kind,in_roi],...]]]*CRC16`

- 发送周期由 100 ms 调整为 150 ms，仍为 64 字节分段和至少 5 ms 段间间隔，忙时跳过而不排旧数据。
- 页面解析兼容旧 v1/v2；新 V3 解码后的 raw 面板仍展示具名字段，wire_version=3。这是显示展开，不是线上实际字节数。
- 主控每 5 ms 处理视觉和 ROI 开合，不依赖遥测；400 ms 过期、100° 轻夹、50° 松开、底盘 EN/PWM 锁定保持。
- 测试同一小样本 CRC 报文（不含换行）196 → 114 字节，含换行按发送周期折算约下降 61%；12+12 目标测试含换行 441 → 359 字节，结合发送周期约下降 46%。真实节省比例依目标和计数长度变化，不代表实测无线吞吐。
- 新固件必须配新页面。桌面同名 HTML 已同步；旧页无法解析 V3。


## 三个新帧防抖（2026-11-14，当前夹爪行为）

取代前面“单帧直接开合”的联调逻辑：连续 3 个不同的下视正常新帧里，均有单个允许物块在 ROI 内，才给 100°；连续 3 个下视正常新帧都出区或无目标，才给 50°。中间出现反向状态会把另一方向的计数清零，未达到 3 帧保持原角度。计数饱和到 3，不会溢出。

只统计主控接收器实际接受的下视新帧，重复报文、主循环重复读取、上视更新不计数。处理同一次队列中的每个完整观测，避免多帧聚集时漏掉中间反向帧；不要求帧编号逐个加一，支持帧编号回绕。

下视超过 400 ms（恰好 400 ms 不过期）、上游 stale/fault、UART 接收故障仍直接松开并清零计数。原有多个物块/危险物入区直接松开保留；恢复后重新数 3 帧。下视目标为估计位置或距离未知时仍按 ROI 判断，不伪造测距有效位。

香橙派视觉代码不变。底盘 EN/PWM 锁定、V3 150 ms 遥测、64 字节分段/5 ms 间隔、下视面板位于 XY 下方及固定列表高度不变。页面仅更新规则说明，不增加遥测字段。
