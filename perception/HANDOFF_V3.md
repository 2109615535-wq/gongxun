## 新版接入方式

使用现有Ultralytics RKNN后端完成预处理、NPU调用、NMS和原图坐标还原。其历史NPU检查日志记录输出形状`(1,14,8400)`，与本地参考导出的九输出格式不同；本次实际调用该模型的Ultralytics后端成功。

`ExistingUltralyticsDetector`核对模型和运行库辅助脚本的SHA256，再调用原项目的`configure_rknn_runtime()`。若模型或辅助脚本以后更新，需重新确认并更新对应校验值，不静默使用另一份文件。

配置使用`detector_pixel_space=raw`：YOLO接收原始BGR图像，检测框保持原图坐标。贴地像素用真实K/D校正后再映射地面，不重复整图去畸变。缺少本车地面标定时仍输出无效位置。

在解压包根目录运行，无需修改原项目：

```bash
/home/orangepi/venvs/yolo-rknn-board/bin/python -m rescue_vision run --config config/orangepi_existing.json --record-video --duration 10 --output recordings/c100_check_01
```

输出目录必须是新目录，默认不发送串口。`serial_protocol=motor2_debug_ascii`仍然保护当前主控UART5，防止发送不兼容的视觉观测帧。

第一次约10秒的采集核验，处理94帧，约12.67帧/秒，USB读取返回到观测记录的延迟P95约142.9ms。

线程设置只作用于本次进程，不修改系统调度、虚拟环境文件或原程序。两次试验条件并非严格相同，不能把微小帧率差异归因于线程设置。

**尚未达到15Hz处理目标。** 上述延迟是无串口发送的采集后软件时间，不是曝光到电机执行的完整延迟，也不是实车运动闭环验收。真实多目标场景的速度和准确率仍需独立测量。
